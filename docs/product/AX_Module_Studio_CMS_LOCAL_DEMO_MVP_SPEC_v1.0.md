# AX Module Studio 로컬 데모 CMS 최소 범위

> 상태: 현재 제품·구현 기준
> 목적: 학원 팀프로젝트의 로컬 발표 시연
> 원칙: 이 문서에 없는 기능은 구현하지 않는다.

## 1. 제품 방향

- CMS 자체가 주인공이 아니라 AX Module Studio의 에이전트 기능을 보여주기 위한 최소 관리 도구다.
- 현재 Frontend 디자인과 스타일을 유지한다.
- 사용자 화면(`/`)과 관리자 화면(`/admin`)은 URL과 화면 구성을 분리한다.
- `Simple is best`를 적용하며 아래 시연 흐름에 필요하지 않은 기능은 추가하지 않는다.
- 기술 스택과 Git/PR 규칙은 유지한다.
- 현재 목표는 로컬 실행이다. AWS 배포는 별도 승인 전까지 범위 밖이다.

## 2. 구현 범위

| 영역 | 최소 기능 |
|---|---|
| 대시보드 | 안내 카드와 기본 메뉴만 표시하는 목업 |
| 회원 관리 | 관리자/사용자 목록, 회원 상세 조회 |
| 계정 | `SUPER_ADMIN`, `GENERAL_ADMIN`, `GENERAL_USER` 시연 계정 각 1개를 미리 준비 |
| 메뉴 관리 | 대메뉴·하위메뉴 목록, 등록, 삭제, 노출 순서, 콘텐츠 또는 게시판 매핑 |
| 콘텐츠 관리 | 특정 메뉴에 연결할 정적 페이지의 목록, 상세, 등록, 수정, 소프트 삭제, 가벼운 편집기 |
| 게시판 관리 | 특정 메뉴에 연결할 게시판/게시물의 목록과 상세, 등록, 수정, 소프트 삭제 |
| 템플릿 관리 | 2~3개 템플릿, 공통 Header/Footer·스타일·사이트명·메인 대표 이미지/문구/버튼 변경, 저장 즉시 사용자 화면 적용 |
| 사용자 화면 | 로그인, 메뉴·콘텐츠·게시물 조회, 선택된 템플릿 적용 확인 |

`SUPER_ADMIN`과 `GENERAL_ADMIN`은 위 CMS 기능에서 차이를 두지 않는다. 향후 RAG 교체,
LLM Key 관리 같은 별도 시스템 기능만 새로운 결정 후 `SUPER_ADMIN` 전용으로 둘 수 있다.

## 3. 최소 데이터

| 데이터 | 필수 항목 |
|---|---|
| 회원 | ID, 로그인 ID, 이름, 역할, 비밀번호 해시 |
| 메뉴 | ID, 메뉴명, 경로, 상위 메뉴 ID, 표시 순서, 매핑 유형, 매핑 대상 ID |
| 콘텐츠 | ID, 작성자, 제목, 내용, 등록시간, 수정시간, 삭제여부, 삭제시간 |
| 게시물 | ID, 게시판 ID, 작성자, 제목, 내용, 등록시간, 수정시간, 삭제여부, 삭제시간 |
| 템플릿 | Template Key, 레이아웃, 색상, 사이트명, Header/Footer, 메인 대표 이미지·문구·버튼 설정 |

삭제는 `deleted_yn=Y`와 `deleted_at`을 남기는 소프트 삭제로 처리한다. 복원 기능은 만들지 않는다.

## 4. 최소 보안

- 로그인과 로그아웃
- 세 역할 구분
- Backend에서 관리자 기능과 사용자 기능 접근 구분
- 비밀번호 해시 저장

MFA, 허용 IP, 세밀한 권한 편집, 보안관리 화면, 접속자 관리 기능은 만들지 않는다.

## 5. 폐기한 범위

다음은 현재 MVP에서 제거한다.

- Approval History, Audit Log, 감사·감리·증거 관리
- Draft, Version, Diff, Preview, Publish, Unpublish, Site Release, Rollback
- 회원 초대, 상태 변경, 권한 변경, 회원 수정·삭제
- 코드관리, 환경설정, 기타설정, 시스템설정, 통계, 접속자 관리
- Template Builder와 템플릿 버전 관리
- Project 격리와 다중 고객사 관리
- 자연어 CMS, RAG, 공공데이터, Model Mapping, PathPolicy, Coding, LLM DevOps, 챗봇

## 6. 범위 통제

팀원은 위 기능을 완성하는 데 필요한 일반적인 구현 세부사항을 자율적으로 결정한다.
예를 들어 입력 검증, 오류 처리, 테스트 코드, 작은 UI 구성요소, 기본 DB 제약조건은 별도 승인을
요청하지 않는다.

다만 다음에 해당하면 구현을 멈추고 팀장에게 승인받는다.

- 이 문서에 없는 화면, 기능, 역할, 상태, 워크플로를 추가하려는 경우
- 폐기한 범위를 다시 도입하려는 경우
- 외부 서비스, Cloud, 새로운 대형 라이브러리를 추가하려는 경우
- 최소 데이터보다 업무 개념을 크게 늘리는 테이블이나 관계를 추가하려는 경우
- 다른 저장소의 공통 계약을 현재 CMS 필요 이상으로 확장하려는 경우

승인 전에는 미래 확장성이나 실운영 대비를 이유로 선행 구현하지 않는다.

## 7. 로컬 완료 기준

1. 세 계정으로 로그인할 수 있다.
2. 관리자 화면에서 회원 목록과 상세를 조회할 수 있다.
3. 메뉴를 등록·삭제하고 콘텐츠 또는 게시판과 연결할 수 있다.
4. 콘텐츠와 게시물을 등록·조회·수정·소프트 삭제할 수 있다.
5. 템플릿 저장 직후 사용자 화면의 공통 영역·메인 정보·스타일이 바뀐다.
6. 사용자 계정으로 연결된 메뉴·콘텐츠·게시물을 조회할 수 있다.
7. 위 흐름을 로컬에서 반복 시연할 수 있다.

이 일곱 항목을 통과하면 현재 CMS MVP는 완료다. 그 이상의 기능은 완료 조건이 아니다.
