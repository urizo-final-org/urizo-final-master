# AI Core 개인 기능 문서 구조 계약

> 기준 문서: [06_ORCHESTRATION_CONTROL.md](06_ORCHESTRATION_CONTROL.md)
> 목적: 2~6번 기능 문서의 내용이 아니라 소유권·아키텍처 경계·기록 구조만 가볍게 맞춘다.

## 공통 구조 슬롯

각 개인 기능 MD는 제목이 달라도 다음 정보를 식별할 수 있으면 된다.

1. 담당자, 현재 단계 또는 상태, 내용 권한
2. 기능 목표와 담당자가 소유하는 업무 범위
3. 주요 실행 구조 또는 데이터·Runtime 경계
4. 다른 기능 및 6번 공통 플랫폼과 맞닿는 계약
5. Guardrail, 제외 또는 후순위 항목
6. 담당자가 확인해야 할 미확정 사항
7. 문서 마지막의 `하위 작업 기록`

6번은 공통 Runtime 플랫폼 문서이므로 다른 기능 문서보다 상세할 수 있다. 다른 담당 문서가 6번의 제목·분량·내용을 그대로 복제할 필요는 없다.

## 문서 역할 분리

- 개인 기능 MD: 현재 방향, 담당 경계, Work ID의 시작·종료 기록
- 6번 문서: Snapshot·Runner·Registry·Approval·Guardrail·MCP 공통 플랫폼 계약
- Closeout·실행 증빙 문서: 종료 당시 검증 증거 보존. 새 Work 원장으로 사용하지 않음
- 공통 운영정책: Work ID·Branch·Commit·PR·Flyway 규칙

## 빠른 확인 방식

- 팀장은 현재 작업에 영향받는 개인 MD만 확인한다.
- 먼저 제목과 상단 메타데이터, 관련 계약 섹션, `하위 작업 기록` 존재만 확인한다.
- 공통 계약 충돌 가능성이 있을 때만 6번의 관련 본문을 읽는다.
- 문서가 작업 중 변경되지 않았다면 종료 시 구조 검사를 반복하지 않는다.

## 판정

- 기본값은 `STRUCTURE PASS`다.
- 표현·제목 순서·표 위치·분량 차이는 `PASS`와 참고사항으로 끝낸다.
- 작업 대상 불명, 변경 유실 가능성이 큰 동시 수정, API·DB·공통 Runtime 변경의 직접 영향 담당자 미확인만 `STRUCTURE BLOCKED`로 둔다.
- 팀장은 다른 담당자의 문서를 직접 수정하지 않고 해당 담당자에게 최소 수정안을 전달한다.
